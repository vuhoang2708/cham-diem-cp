# Technical Investigation Report: AmiBroker COM Automation via Python
**Date**: 2026-05-17  
**Investigator**: AI-assisted (Claude)  
**Status**: Investigation complete — blocker unresolved

---

## 1. Objective

Automate extraction of FA_MCDX (Banker Smart Money) and FA_RRG (Relative Rotation Graph) indicator values from AmiBroker using Python COM automation, for 100 Vietnamese stock symbols (VN100 index). These indicators are proprietary functions provided by the FireAnt plugin installed in AmiBroker.

**Target**: Replace a Playwright-based web scraper (~75 min for VN100) with direct AmiBroker data access (~2 min target).

## 3. What Was Confirmed Working

### 3.1 Basic COM Connection
```python
import win32com.client
ab = win32com.client.Dispatch("Broker.Application")
ab.Version  # → "6.30.0"
```
Connection succeeds reliably with 32-bit Python. Fails with 64-bit Python (see §4.1).

### 3.2 Reading Stock Data
```python
ab.Stocks("VCB").Quotations  # → 4210 OHLCV bars
```
Direct OHLCV data access works. However FA_MCDX and FA_RRG are not accessible this way — they are computed by the FireAnt plugin during AFL execution only.

### 3.3 Opening .apx Analysis File
```python
doc = ab.AnalysisDocs.Open(r"C:\Users\Public\vn100_export.apx")
# → returns COMObject, no exception
```
Works correctly once the file format is right (see §4.2).

### 3.4 Triggering a Scan
```python
doc.Run(1)  # 1 = Scan mode
# IsBusy=True for ~89s (8887 symbols) or ~5 min (with FA_MCDX)
```
The scan executes. AmiBroker processes symbols. `IsBusy` transitions True → False when complete.

### 3.5 Available COM Methods on `Broker.Application`
Confirmed present via attribute probing:
`Version`, `AnalysisDocs`, `Stocks`, `Documents`, `ActiveWindow`, `ActiveDocument`, `LoadDatabase`, `SaveDatabase`, `RefreshAll`, `Import`, `Log`, `Quit`

## 4. Issues Encountered and What Was Tried

### 4.1 Bitness Mismatch (RESOLVED)

**Problem**: 64-bit Python + 32-bit AmiBroker → exception code `e0434352` (.NET CLR error) when calling `AnalysisDocs.Open()`.

**Fix**: Installed Python 3.12 32-bit, created `venv32`. All subsequent tests use `venv32\Scripts\python.exe`.

---

### 4.2 Wrong File Format for AnalysisDocs.Open() (RESOLVED)

**Problem**: Calling `AnalysisDocs.Open("ami_bridge.afl")` → `RPC_E_SERVERFAULT (-2147417851)`. AmiBroker crashes server-side.

**Discovery**: `Open()` requires `.apx` XML project files, not `.afl` formula files.

**Fix**: Obtained a real `.apx` file saved from AmiBroker UI (`template.apx`). Confirmed correct XML structure:
```xml
<?xml version="1.0" encoding="ISO-8859-1"?>
<AmiBroker-Analysis CompactMode="0">
  <General>
    <FormatVersion>1</FormatVersion>
    <Symbol>VCB</Symbol>
    <FormulaPath>Custom\ami_bridge.afl</FormulaPath>
    <FormulaContent></FormulaContent>
    <ApplyTo>0</ApplyTo>
    ...
```
Created `backend/create_apx.py` to generate correctly formatted `.apx` files.

---

### 4.3 Inline FormulaContent Not Executed (PARTIALLY RESOLVED)

**Problem**: `.apx` with `<FormulaPath></FormulaPath>` (empty) and formula in `<FormulaContent>` → scan completes instantly (`IsBusy=False` after 1s), no output.

**Finding**: When `FormulaPath` is empty, AmiBroker does not execute the inline `FormulaContent` during a COM-triggered scan. The scan runs on 0 symbols effectively.

**Workaround**: Use `<FormulaPath>Custom\ami_bridge.afl</FormulaPath>` pointing to a real `.afl` file on disk. With this, `IsBusy=True` for the expected duration, confirming the formula is being loaded and executed.

---

### 4.4 ApplyTo=1 (Current Symbol) Runs on 0 Symbols (NOT RESOLVED)

**Problem**: With `<ApplyTo>1</ApplyTo>` (current chart symbol), scan completes instantly with no output.

**Attempted fixes**:
- `doc.SetSymbol("VCB")` → `AttributeError: <unknown>.SetSymbol`
- `doc.SetApplyTo(1)` → `AttributeError: <unknown>.SetApplyTo`
- `doc.SetFilterSymbol("VCB")` → `AttributeError: <unknown>.SetFilterSymbol`
- `ab.ActiveDocument.Name = "VCB"` → `Property '<unknown>.Name' can not be set`

None of these methods exist on the COM object in this version. The `AnalysisDoc` COM object exposes only `Run()` and `IsBusy` as confirmed working properties.

**Conclusion**: There is no way to set the target symbol for a scan via COM in this version. `ApplyTo=1` with no active chart symbol = 0 symbols scanned.

---

### 4.5 CategoryAddSymbol / Watchlist API Not Available (NOT RESOLVED)

**Problem**: To scan only VN100 symbols (not all 8887), needed to use a watchlist (`ApplyTo=3`).

**Attempted**:
```python
ab.CategoryAddSymbol(4, 0, "VCB")  # type=4 (Watchlist), index=0
# → AttributeError: Broker.Application.CategoryAddSymbol
```

Also tried: `CategoryGetSymbols`, `CategoryCreate`, `GetWatchlist`, `AddToWatchlist` — all `AttributeError`.

**Conclusion**: Watchlist manipulation via COM is not available in this version.

---

### 4.6 fopen() in AFL Does Not Write Files When Triggered via COM (CORE BLOCKER)

This is the primary unresolved issue.

**Setup**: AFL formula (`ami_bridge.afl`) contains:
```afl
outfile = "C:\\Users\\Public\\ag_bridge_out.txt";
fh = fopen(outfile, "w");
if (fh) {
    fputs("symbol=" + Name() + "\n", fh);
    fputs("banker=" + NumToStr(LastValue(FA_MCDX(50,1.5,50,20)), 1.6) + "\n", fh);
    // ... more fields ...
    fclose(fh);
}
Filter = 1;
```

**Test 1 — Full formula, `C:\Windows\Temp` path**:
- Scan ran 89 seconds on 8887 symbols
- No file created at `C:\Windows\Temp\ag_bridge_out.txt`

**Test 2 — Full formula, `C:\Users\Public` path**:
- Scan ran 89 seconds
- No file created at `C:\Users\Public\ag_bridge_out.txt`

**Test 3 — Minimal AFL, only fopen/fputs**:
```afl
// test_write.afl — no FA_MCDX, no FA_RRG, just file write
fh = fopen("C:\\Windows\\Temp\\ami_test.txt", "w");
if (fh) {
    fputs("hello from amibroker\n", fh);
    fclose(fh);
}
Filter = 1;
```
- Scan ran to completion (`IsBusy` True → False)
- No file created

**Test 4 — VN100 export formula, `C:\Users\Public\ami_<SYMBOL>.txt` per symbol**:
- Scan ran ~5 minutes on 8887 symbols
- Zero files created in `C:\Users\Public\`

**Test 5 — UAC VirtualStore hypothesis**:
- Checked `%LOCALAPPDATA%\VirtualStore\Windows\Temp\` for redirected writes
- Directory does not exist → UAC virtualization not active → hypothesis eliminated

**Summary of fopen tests**:

| Test | Formula | Output Path | Scan Duration | Files Created |
|------|---------|-------------|---------------|---------------|
| 1 | Full (FA_MCDX + FA_RRG) | `C:\Windows\Temp\` | 89s | 0 |
| 2 | Full (FA_MCDX + FA_RRG) | `C:\Users\Public\` | 89s | 0 |
| 3 | Minimal (fopen only) | `C:\Windows\Temp\` | ~89s | 0 |
| 4 | Per-symbol export | `C:\Users\Public\ami_*.txt` | ~5 min | 0 |

**Observation**: `fopen` in AFL works correctly when formula is run from AmiBroker UI (chart window or Analysis window opened manually). It does not produce output when the same formula is run via `AnalysisDocs.Run()` called from Python COM.

**Possible explanations** (not confirmed, for the next investigator to verify):

1. **Sandboxed execution context**: AmiBroker may run COM-triggered scans in a restricted security context that blocks file I/O. This could be intentional in the crack build to prevent automation.

2. **Silent fopen failure**: `fopen` may be returning 0 (failure) silently. The `if(fh)` block is never entered. The scan "completes" because `Filter=1` still executes. There is no way to surface the fopen error from AFL.

3. **Working directory issue**: AFL `fopen` with absolute paths should not be affected by working directory, but this has not been ruled out with a relative path test.

4. **COM apartment threading**: The scan may execute in a different thread/apartment where file handles are not valid. Unlikely given absolute paths, but not ruled out.

5. **Crack-specific restriction**: The unofficial build may have patched out file I/O during COM-triggered scans specifically.

## 6. Key Open Question for Next Investigator

**The single most important thing to verify**: Does `fopen` in AFL work when triggered via `AnalysisDocs.Run()` on a **licensed, non-cracked** AmiBroker installation?

If yes → the crack build is the problem, and a licensed copy would solve it.  
If no → this is a fundamental AmiBroker COM limitation regardless of license.

A quick test: run `test_write.afl` (just `fopen` + `fputs("hello")` + `Filter=1`) via COM on a licensed AmiBroker. If `C:\Windows\Temp\ami_test.txt` appears → file I/O works in licensed builds.
